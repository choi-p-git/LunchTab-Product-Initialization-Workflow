Under each sales business type it is possible to conﬁgure a number of pages that will be displayed on the Point of Sale (POS) system. These pages can be used to provide quick access to the most commonly sold items, and to provide custom items that represent account credits, debits or discounts that not di- rectly related to products in the catalog. Self service conﬁgurations can also be created to provide a simpliﬁed interface for cus- tomers to place their own orders without the attendance of a cashier, and these can be linked to a restricted set of product pages. POS pages can be created, edited and deleted from the POS Pages view under each sales business type. To create a POS page, select Add POS Page from the actions menu. Once your POS pages and items are conﬁgured, you can use the POS Builder to create a custom layout for the POS system. Select the page you wish to edit to open the POS builder canvas. Use the tabs and ﬁlters on the left column to locate the products or custom items you wish to add to the currently selected POS page. Add an item to the page day by either dragging it onto the canvas or by clicking the + button. Once items are added to the canvas you can drag to reorder them, which will deﬁne the order in which they will appear on the POS. To remove an item from the page, click the x button to remove it from the canvas. POS Builder Adding / Removing / Ordering Items

For Cafeteria sales business types, a page for each of the day's active menus are auto- matically generated on the POS. Along with the POS pages you have deﬁned, there will be an entry representing a tem- plate for these menus pages. For example if your sales business type is named Cafeteria you'll see an entry for Cafeteria Menus in the list. This template can be conﬁgured in the same way as your standard POS pages, and the items added will be inserted into the automatically generated pages alongside the menu items for that day. If it is not desirable for a menu to appear as a page on the POS, this can be conﬁgured using the Hide From POS setting on the menu conﬁguration. See the Menus documen- tation for more information. Self-service conﬁgurations can be created to provide a simpliﬁed and restricted expe- rience for customers to place their own orders without the attendance of a cashier. POS self-service conﬁgurations can be created, edited and deleted from the POS Self Service view under each sales business type. For further details on activating these conﬁgurations and the resulting behavior in the POS application, see the Self Service documentation within the vending outlets section. To create a self-service conﬁguration, select Add Self Service Conﬁg from the actions menu. Value Description Name The name of the conﬁguration. Mode Either Check In , Self Service or Balance Check . There are three distinct modes available for self-service conﬁgurations, Check In, Self Service and Balance Check. When a POS is conﬁgured with Self Service mode, an interface similar to the normal cashier experience will be presented while removing all administrative functions. A limited set of POS pages can be deﬁned for self-service use, but there is no require- ment to do so. If no pages are deﬁned under the conﬁg, the same product pages will be available as to a standard cashier. Self Service Modes Self Service

When in this mode, users may only make purchases using their account balance, and will not be able to use cash or card payments. When a Check In self-service mode is active, the POS will provide a simpliﬁed experi- ence where users can only check in to the outlet and receive a predeﬁned product. The screen will prompt for the next consumer to present their credentials, and upon successful authentication the predeﬁned product will be purchased immediately using their account balance. Once the purchase is complete, the screen will return to the prompt for the next con- sumer to check in. When a Balance Check self-service mode is active, the POS will display the current bal- ance of the user's associated Lunchtab family accounts. The screen will prompt for the next consumer to present their credentials, and upon successful authentication the user's balances will be shown for the deﬁned period be- fore moving onto the next customer.
